# davidburke.me

## Project Overview
This project is a personal website and blog for David Burke (`davidburke.me`), built using [Hugo](https://gohugo.io/), a fast static site generator written in Go. The site utilizes the [Stack](https://github.com/CaiJimmy/hugo-theme-stack) theme, providing a modern, responsive, and card-style design. The content is written exclusively in English Markdown.

## Key Technologies
*   **Static Site Generator:** Hugo (Extended version)
*   **Theme:** Stack (`themes/Stack`)
*   **Deployment:** GitHub Actions deploying to GitHub Pages

## Project Structure
*   `config/_default/`: Contains the main configuration files (`hugo.toml`, `params.toml`, `languages.toml`, `menu.toml`, etc.).
*   `content/`: Contains the Markdown files for the website's pages and blog posts. Content is organized by `post/`, `page/`, and `categories/`.
*   `themes/Stack/`: The Hugo theme repository (often a git submodule).
*   `layouts/`: Custom overrides for the theme's HTML templates.
*   `public/`: The built static site (generated by Hugo).
*   `.github/workflows/hugo.yaml`: The GitHub Actions workflow for building and deploying the site to GitHub Pages.
*   `graphify-out/`: Contains the output of the Graphify knowledge graph tool, including `graph.html` and `GRAPH_REPORT.md` which map out the relationships within the `content/` folder.

## Building and Running
To develop or build the site locally, you need to have Hugo installed (the Extended version is recommended for features like SCSS/SASS processing).

*   **Local Development Server:**
    Run the following command to start a local web server with live reload:
    ```bash
    hugo server -D
    ```
    (The `-D` flag includes draft posts).

*   **Build Static Site:**
    To build the production-ready static site into the `public/` directory:
    ```bash
    hugo --minify
    ```

## Development Conventions
*   **Content Creation:** New posts should be created in the `content/post/` directory using Markdown. Use `hugo new post/my-new-post.md` to utilize the archetypes.
*   **Front Matter:** Files use YAML or TOML front matter for metadata (title, date, categories, tags).
*   **Drafts as References:** Select reference documentation (like Math Typesetting, Mermaid Diagrams) are kept in the `content/post/` directory but marked with `draft: true` so they don't deploy to the production site but can be viewed locally.
*   **Language:** The content directory is English-only (all non-English `.ja.md` and `.zh.md` files have been removed).
*   **Footer Credits:** The "designed by" footer credit is overridden in the local `i18n/en.toml` file to point to Jimmy's website.
*   **Footer Overrides:** The copyright section in the footer is hidden by overriding the respective partial in the local `layouts/partials/` directory.
*   **Deployment:** The `main` branch acts as the production branch. Pushing to `main` automatically triggers the GitHub Actions workflow to build and deploy the site.

    *   **Tagline:** Moved to a new horizontal `top-header` bar with responsive hiding logic.
    *   **Animations Toggle:** Added global control to enable/disable site animations.
    *   **Tag Coloring:** Implemented a Notion-inspired color palette (9 standard colors).
    *   **White Text:** Enforced for all tags across both modes.

*   **Accessibility:**
